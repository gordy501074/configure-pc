# План: AI-инструмент «Подбор с помощью AI-бота»

## 1. Цель

Добавить в раздел **«Автоподбор»** (`/auto`) новый режим — **«Подбор с помощью AI-бота»**:
чат-бот, который узнаёт бюджет, профессию/интересы и хобби пользователя, а затем
предлагает наиболее сбалансированную **готовую** или **кастомную** конфигурацию
**исключительно из реальных данных сайта** (готовые сборки, компоненты, действующие
цены активного прайс-листа выбранного продавца).

## 2. Зафиксированные решения (по итогам уточнений)

| Вопрос | Решение |
| --- | --- |
| Интеграция | Отдельный **режим-вкладка** рядом с существующим опросом на `/auto`. Опрос из 4 шагов и его тесты не ломаются. |
| Достоверность | **Гибрид**: LLM ведёт диалог и извлекает требования в JSON; **детерминированный серверный движок** ранжирует готовые сборки и собирает кастом; LLM только объясняет выбор. Ноль галлюцинаций по ценам/совместимости. |
| Модель | По умолчанию **`google/gemini-2.5-flash-lite`**, переопределяется через `OPENROUTER_CHAT_MODEL`. |
| Доступ | **Публично** (гость и авторизованные), как и текущий `/auto`. Сохранение/заказ — как сейчас, требуют роли `customer`. |
| История чата | **В памяти** (состояние сессии/компонента), без новых таблиц БД. Финал ведёт на существующий экран результата/карточку. |
| Формат ответа | **Стриминг по токенам** (NDJSON, как `/api/ai/component-image`). |
| Приоритет выбора | Сначала подходящая **валидная готовая** сборка; если нет — **кастомная** из компонентов. |
| Защита | **In-memory rate-limit** без БД (лимит сообщений/сессии и по IP, ограничение длины истории/сообщения). |

## 3. Архитектура и поток данных

```
AutoChat (React)
  └─ POST /api/ai/advisor/chat  { messages, sellerId }   (NDJSON-стрим)
       ├─ rate-limit (session/IP)
       ├─ 503 ai_not_configured (если нет ключа) — обычным JSON ДО стрима
       ├─ LLM (gemini-2.5-flash-lite, stream:true):
       │    стримит `delta` (текст), в конце ответа — фенсed-JSON:
       │    {"requirements":{...},"ready":bool}
       ├─ если ready=false → done (бот задаёт следующий вопрос)
       └─ если ready=true:
            1. детерминированный движок (src/lib/aiAdvisor.ts):
               rankReadyBuilds(catalog, requirements) → иначе buildAdvisorConfig(...)
            2. сервер строит recommendation из РЕАЛЬНЫХ данных/цен
            3. event 'recommendation' → фронт открывает карточку/результат
```

**Почему гибрид:** каталог нельзя целиком класть в промпт (дорого/медленно/галлюцинации).
LLM получает только краткий контекст (категории, теги назначения, примеры названий) и
извлекает требования; конкретику (цены, совместимость, слоты) считает сервер тем же
кодом, что и остальное приложение (`compatibility.ts`, прайс-листы).

### Контракт одного ответа LLM (стрим + JSON-конверт)

- Стрим отдаёт **только** пользовательский текст (`delta`).
- В конце ответа модель дописывает строку-конверт в коде-фенсе:
  `{"requirements": {...}, "ready": false}`.
- Сервер накапливает текст, отделяет конверт от видимого текста (фенс не показывается),
  парсит JSON через существующий `parseJsonFromText`.
- Если JSON не распознан — `requirements` сохраняются прежними, бот продолжает диалог
  (fail-safe, без падения всего ответа). Это же решение при нестабильном JSON —
  резервный вариант: второй дешёвый `chatJson`-вызов на извлечение требований.

## 4. Выбор модели OpenRouter

> Прямой доступ к `openrouter.ai` из текущей среды блокируется (HTTP 403 — то же
> ограничение, что описано в README). Ниже — рекомендация на основе уже принятых в
> проекте эмпирических выводов и требований задачи; финальный выбор подтверждается
> прогоном-бенчмарком (см. задачу B0).

Критерии: **дешевизна + скорость + релевантность на русском** при малой нагрузке на LLM
(диалог и извлечение требований; тяжёлый подбор делает детерминированный движок).

| Модель | Цена (in/out за 1M) | Почему |
| --- | --- | --- |
| **`google/gemini-2.5-flash-lite`** (рекомендуется) | ~$0.10 / ~$0.40 | Самая дешёвая и быстрая из рассмотренных, хороший русский, стабильный JSON. Уже используется в проекте (поиск фото `OPENROUTER_IMAGE_MODEL`). |
| `openai/gpt-4o-mini` | ~$0.15 / ~$0.60 | Чуть надёжнее в следовании инструкциям/структурном выводе; близкая цена. |
| `google/gemini-2.5-flash` | ~$0.30 / ~$2.50 | Сильнее в рассуждениях, дороже/медленнее — запас на сложные формулировки. |
| `deepseek/deepseek-v4.1-flash` | десятки микроцентов | Уже используется для описаний; быстрая и дешёвая, но заточка под короткий текст. |

Итог: **дефолт `google/gemini-2.5-flash-lite`**, переопределяемо `OPENROUTER_CHAT_MODEL`.
Промпт держим компактным (диалог + требования), поэтому стоимость/латентность минимальны.

## 5. Типы и контракты

### `src/types/index.ts`

```ts
export interface AdvisorRequirements {
  budget?: number;                 // ₽
  usage?: Usage;                   // gaming | work | video | universal
  interests?: string[];            // профессии/хобби (свободный текст)
  priorities?: string[];           // «тишина», «производительность», «цена»
  ecosystem?: Ecosystem;           // intel | amd
  notes?: string;
}

export interface AdvisorMessage { role: "user" | "assistant"; content: string; }

export type AdvisorStreamEvent =
  | { event: "start"; deadlineMs: number }
  | { event: "delta"; text: string }
  | { event: "requirements"; data: AdvisorRequirements }
  | { event: "recommendation"; kind: "ready" | "custom";
      readyPcId?: string; config?: Config; summary: string }
  | { event: "done" }
  | { event: "error"; error: string };
```

### API (в `src/server/index.ts`)

`POST /api/ai/advisor/chat` — **публичный** (без `requireSellerOrAdmin`), NDJSON.
- Тело: `{ messages: AdvisorMessage[], sellerId?: string }`.
- Валидация: непустой последний `user`, длина сообщения ≤ 2000, история ≤ 20 сообщений.
- До старта стрима: `503 { error: "ai_not_configured" }` при отсутствии ключа;
  `429 { error: "rate_limited" }` при превышении лимита; `400 { error: "invalid_input" }`.
- В стриме — события из `AdvisorStreamEvent`.
- Аборт по `res.on("close")` — как в `/api/ai/component-image`.

### Клиент (`src/lib/api.ts`)

`streamAdvisorChat({ messages, sellerId }, { signal, onEvent })` — аналог
`streamComponentImages` (NDJSON-ридер). Возвращает накопленные `recommendation`/текст.
Дополнительно утилита `advisorErrorMessage(code)` для дружелюбных сообщений.

## 6. Детерминированный движок — `src/lib/aiAdvisor.ts` (чистые функции)

Экспортируется и используется только на сервере; покрывается юнит-тестами.

```ts
export interface AdvisorCatalog {
  ready: ReadyPc[];                                 // уже валидные и с ценами
  parts: Record<ComponentCategory, Part[]>;         // orderable-компоненты
}

export function normalizeRequirements(raw: unknown): AdvisorRequirements;

/** Готовая сборка-победитель (бюджет/назначение/интересы) или null. */
export function rankReadyBuilds(ready: ReadyPc[], req: AdvisorRequirements): ReadyPc | null;

/** Кастомная сборка по требованиям (адаптация логики survey.ts под интересы). */
export function buildAdvisorConfig(
  req: AdvisorRequirements, catalog: AdvisorCatalog,
): Config;

/** Единая точка входа: готовое в приоритете, иначе кастом. */
export function recommend(
  req: AdvisorRequirements, catalog: AdvisorCatalog,
): { kind: "ready"; readyPc: ReadyPc; summary: string }
 | { kind: "custom"; config: Config; summary: string };
```

Правила ранжирования (детерминированные, без LLM):
- Бюджет: допуск ±15–20%; штраф за перерасход; бонус за близость к бюджету.
- Назначение: соответствие `usage` (готовые сборки имеют `usage`) и тегам интересов
  (например `видеомонтаж/3D → video`, `игры/стриминг → gaming`).
- Приоритеты: «тишина» → бонус сборкам с СЖО/тихим охлаждением; «цена» → минимизация цены.
- Кастом: переиспользовать score-функции `survey.ts` (`budgetScore`, подбор CPU/GPU/RAM/PSU/кулера),
  добавив интерес-веса (например, монтаж → больше ядер/памяти, игры → bench GPU).

## 8. Обработка ошибок и защита

- Нет ключа → `503 ai_not_configured` (обычный JSON **до** стрима); UI — понятное сообщение.
- Ошибка провайдера → `502 ai_failed` / событие `{event:"error"}`.
- Rate-limit → `429 rate_limited`; лимит на сессию/IP, окно скользящее, `Map` с очисткой.
- Обрыв соединения клиентом → `AbortController` прерывает LLM-вызов и загрузку.
- Секреты: `OPENROUTER_API_KEY` только на сервере, не логируется и не отдаётся фронту.
- Промпт-инъекции: требования валидируются `normalizeRequirements` (типы/enum/диапазоны),
  бот не управляет ценами — их всегда считает движок.

## 10. Риски

| Риск | Митигизация |
| --- | --- |
| Модель не всегда дописывает JSON-конверт | Fail-safe: сохраняем прежние требования, продолжаем диалог; резерв — отдельный `chatJson`-вызов на извлечение. |
| Стоимость при длинных диалогах | Rate-limit + ограничение истории/длины + компактный промпт (без дампа каталога). |
| Рассинхрон цен/наличия | Подбор всегда по живым данным сервера (активный прайс выбранного продавца). |
| Задержка до первого токена | Стриминг + короткий системный промпт; показывать индикатор «печатает». |

## 11. Валидация (критерии готовности)

1. Гость открывает `/auto` → вкладка «Подбор с помощью AI-бота» → ведёт диалог, получает
   бюджет/интересы/хобби и в итоге **конкретную** сборку с реальными ценами.
2. Готовая сборка предлагается, когда она укладывается в бюджет/назначение; иначе — кастом.
3. Кнопка ведёт на `/ready/:id` (готовая) или `/auto/result` (кастом); работают
   Оформить/Сохранить/Редактировать/Поделиться для `customer`.
4. Без ключа — понятное сообщение; превышение лимита — «слишком много сообщений».
5. `npm run test:unit:cov`, `npm run test:typecheck`, `npm run build`, `npm run test:regression` — зелёные.
