# Fake door: сравнение конфигураций, рассрочка Альфа-Банка и CTR в админке

## Цель

Добавить два fake door (заглушки «Скоро») и дашборд их CTR:

1. **Сравнение конфигураций** (раздел «Конфигурации» профиля Клиента): кнопка
   «Добавить к сравнению» на карточке конфигурации + кнопка «Сравнить», на которую
   вешается CTR. Выбирается не более 3 конфигураций. Клик по «Сравнить» открывает
   модалку «Скоро» и трекает CTR.
2. **Рассрочка Альфа-Банка** (Конфигуратор, только `isCustomer`): отдельный блок с
   двумя схемами — «20% предоплаты, 0 переплат, 6 месяцев» и «50% предоплаты,
   0 переплат, 12 месяцев». A/B: каждый посетитель видит ровно одну схему
   (детерминированно по чёт/нечёт `sessionId`). Клик по схеме открывает модалку
   «Скоро» и трекает CTR схемы. Существующий рабочий блок 0-0-4 (`InstallmentPlan`)
   сохраняется без изменений.
3. **CTR в разделе «Администрирование»** профиля Администратора: текущая вкладка
   «Администрирование пользователей» переименовывается в «Администрирование», внутри
   раздела добавляется блок с таблицей CTR по fake door (клики, просмотры, CTR%).

## Уже принятые решения (уточнены с пользователем)

- Fake door — только заглушка: сравнение и новые схемы рассрочки **не реализуются**.
- Оба fake door при клике показывают **модалку «Скоро»**.
- CTR-блок — **прямо в разделе «Администрирование»** (без новых вкладок).
- Таблица CTR: **клики + CTR% + просмотры**.
- Список сравнения хранится в **localStorage** (переживает переходы).
- Схемы рассрочки — **отдельный блок**, блок 0-0-4 **сохраняется**.
- Знаменатель CTR = **`page:view` экрана-носителя** (Конфигуратор `/config` для
  рассрочки, Профиль `/profile/configs` для сравнения).
- A/B схем рассрочки — **чёт/нечёт по `sessionId`**.
- Блок рассрочки — **только для `isCustomer`**.

## Ключевые факты кодовой базы

- Аналитика уже готова: атрибут `data-track` на элементе → глобальный capture-listener
  в `src/lib/analytics/auto.ts:110-126` → событие `ui:click` с payload `{ name, ...payload }`
  (`payload` из `data-track-payload-json`). События пишутся в SQLite `analytics_events`.
- `page:view` c payload `{ route }` и колонкой `route` пишется авто-интеграцией
  (`src/lib/analytics/auto.ts:68-85`) при навигации и первой загрузке.
- Серверный DAO `src/server/repository/analytics.ts` уже отдаёт `append/count/recent/flows`.
- `GET /api/analytics` — приём событий; admin-guard'ы: `requireAdmin` (`src/server/index.ts:100`).
- `analytics_events.payload` — TEXT с JSON; JSON1 (`json_extract`) доступен в bundled SQLite.
- Схема БД (`db/schema.sql`) уже содержит `analytics_events` → **миграция не нужна**.
- Клик-трекер срабатывает по `closest("[data-track]")` — работает и когда клик открывает модалку.
- Вкладка админа задаётся в `src/screens/Profile.tsx:55` (`label: "Администрирование пользователей"`),
  заголовок экрана `Admin.tsx` уже `Администрирование` (`src/screens/Admin.tsx:241`).
- Модалка — `Modal` из `src/components/ui` (`src/components/ui/Modal.tsx`).
- `redact` не трогает ключи `name`/`scheme`/`route` (не PII) — payload сохраняется.

Создать `src/lib/analytics/fakeDoors.ts`:
- Тип `FakeDoorDef { id: string; label: string; hostRoute: string }`.
- `FAKE_DOORS: FakeDoorDef[]`:
  - `{ id: "fake_door_compare", label: "Сравнение конфигураций", hostRoute: "/profile/configs" }`
  - `{ id: "fake_door_installment_20_6", label: "Рассрочка 20% / 6 мес", hostRoute: "/config" }`
  - `{ id: "fake_door_installment_50_12", label: "Рассрочка 50% / 12 мес", hostRoute: "/config" }`
- Плюс impression-события для A/B-схем (см. п.2): добавить в каталог поле `impressionEvent`/`impressionId`
  или отдельную карту `SHOWN_IMPRESSION`.

### 2. Типы аналитики
В `src/lib/analytics/events.ts`: расширить union `AnalyticsEventName` строкой
`"fake-door:impression"` (имя события для показа схемы; клики остаются `ui:click`).

### 3. Логика A/B схем рассрочки (чистая, тестируемая)
Создать `src/lib/installmentAb.ts`:
- `pickInstallmentScheme(key: string): "20-6" | "50-12"` — FNV/31-хеш строки, чёт/нечёт.
- `installmentSchemeKey(): string` — `getSessionId() ?? localStorage["confi_analytics_anon_id"] ?? ""`.
- Экспорт каталога схем: `INSTALLMENT_SCHEMES = { "20-6": { prepayPct: 20, months: 6, ... }, "50-12": {...} }`.

### 4. Логика списка сравнения (чистая, тестируемая)
Создать `src/lib/useCompare.ts`:
- Константа `MAX_COMPARE = 3`, ключ `confi_compare_configs`.
- Чистая `toggleCompare(list: string[], id: string, max = MAX_COMPARE): string[]`
  (add/remove, не превышая `max`; при превышении — без изменений).
- Хук `useCompare(validIds?: string[])`: читает/пишет localStorage, отдаёт
  `{ ids, toggle, clear, isSelected, canCompare }`; при наличии `validIds` вычищает
  устаревшие id (удалённые конфигурации). Парсинг — в try/catch, при ошибке — `[]`.

### 5. Переиспользуемая модалка «Скоро»
Создать `src/components/shared/ComingSoonDialog.tsx` (обёртка над `Modal`):
- Пропсы `{ open, onClose, title, description }`; кнопка «Понятно».
- Используется обоими fake door.

### 6. Fake door «Сравнение» в профиле Клиента
`src/screens/Profile.tsx`, ветка `activeTab === "configs"`:
- Подключить `useCompare(configs.map(c => c.id))`.
- Над списком — тулбар: текст «Выбрано для сравнения: N из 3», кнопка

  рядом «Очистить» (кнопка без трекинга или с отдельным payload).
- В карточке каждой конфигурации — кнопка **«Добавить к сравнению»** /

  при клике на переполнении — `toast("Можно сравнить не более 3 конфигураций", "info")`.

### 7. Fake door рассрочки в Конфигураторе
Создать `src/components/shared/InstallmentFakeDoor.tsx`:
- Показывает только одну схему: `pickInstallmentScheme(installmentSchemeKey())`.
- Визуальный стиль Альфа-Банка (красные токены) по образцу `InstallmentPlan`.
- Превью: предоплата (20%/50% от `total`) и ежемесячный платёж (остаток / число месяцев);
  при `total <= 0` — текст без сумм.
- `useEffect` при монтировании трекает показ:
  `analytics.trackRaw({ event: "fake-door:impression", payload: { name: <schemeId> } })`.
- Основной кликабельный элемент (`role="button"`, `tabIndex=0`, Enter/Space) с
  `data-track={schemeId}` (`fake_door_installment_20_6` | `fake_door_installment_50_12`)
  открывает `ComingSoonDialog` («Схема рассрочки скоро появится»).
- Пропсы `{ total: number }`.
- В `src/screens/CustomConfig.tsx` в `<aside>` рендерить:
  ```tsx
  {isCustomer ? <InstallmentFakeDoor total={stats.totalPrice} /> : null}
  ```
  рядом с существующим `InstallmentPlan` (сохранить как есть).

### 8. Серверная агрегация CTR
`src/server/repository/analytics.ts` — добавить в интерфейс и реализацию:
- `fakeDoorClicks(from: string | null, to: string): { name: string; clicks: number }[]`
  ```sql
  SELECT json_extract(payload,'$.name') AS name, COUNT(*) AS clicks
  FROM analytics_events
  WHERE event='ui:click' AND json_valid(payload)
    AND json_extract(payload,'$.name') LIKE 'fake_door%'
    AND (@from IS NULL OR ts >= @from) AND ts <= @to
  GROUP BY name
  ```
- `routeViews(routes: string[], from, to): { route: string; views: number }[]`
  (для `event='page:view'`, `GROUP BY route`, фильтр `route IN (...)`).
- `impressions(names: string[], from, to): { name: string; impressions: number }[]`
  (для `event='fake-door:impression'`, `json_extract(payload,'$.name')`).
- `count()`/`recent()`/`flows()` не менять.

`src/server/index.ts` — новый admin-эндпоинт (после `/api/admin/analytics`):
- `GET /api/admin/fake-door-ctr?period=` (`requireAdmin`; период через существующий
  `parsePeriod`/`periodRange`).
- Собирает строки по `FAKE_DOORS`: `{ id, label, views, clicks, impressions, ctr }`,
  где `views` = `routeViews` по `hostRoute`, `ctr = views > 0 ? clicks / views : null`.

### 9. Клиентский API и типы

- `src/lib/api.ts`: `fetchFakeDoorCtr(period): Promise<FakeDoorCtrRow[]>`

## Риски и примечания

- **A/B-знаменатель**: CTR схем рассрочки считается к общим `page:view` `/config`,
  который включает визиты без показа блока (гости/продавцы). Для честного A/B добавлена
  колонка «Показы» из `fake-door:impression` (показ ровно одной схемы). Если нужен
  строгий A/B-CTR — в будущем перейти на `impressions` как знаменатель для схем.
- **Приватность**: payload fake door не содержит PII; `redact` сохраняет `name`/`scheme`.
- **Локалка/StrictMode**: `useEffect` impression в StrictMode в dev может вызвать
  двойной трекинг показа — допустимо (dev), либо дедуплицировать через `useRef`.
- **Устаревшие id сравнения**: чистятся при загрузке по актуальному списку конфигураций.
- **Изменения схемы БД не требуются** — миграции не нужны.
- Тестовое переименование вкладки затрагивает существующие Playwright-ассерты
  (обновить обязательно, иначе падение regression).

## Вне scope

- Реальная страница сравнения и реальные новые схемы рассрочки (это fake door).
- Серверное хранение выбора сравнения (остаётся localStorage).
- Изменение существующего блока рассрочки 0-0-4 и логики заказов `alpha`.
