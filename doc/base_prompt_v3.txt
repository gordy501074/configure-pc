# PC configurator web application (Confi)

> Скомпилированная спецификация-промпт (v3). 

## 1. Назначение

Веб-конфигуратор ПК с тремя путями выбора сборки (готовые ПК, ручной конфигуратор, автоподбор по опросу), живой проверкой совместимости, сохранением в профиль, отзывами и оформлением заказа. Поддерживает покупку в рассрочку 0-0-4 от Альфа-Банка с отдельной формой заявки. Демо-проект: все компоненты, цены и отзывы вымышлены и хранятся локально в `localStorage` (префикс `alfagen:`); серверного бэкенда и реальной базы нет. UI и данные — на русском языке.

## 2. Технологический стек (фактический)

- **Язык/рамка**: TypeScript 5.6 (strict, `noUnusedLocals`, `noUnusedParameters`, `jsx: react-jsx`), React 18.3, `@types/react`.
- **Сборщик**: Vite 5, плагины `@vitejs/plugin-react` + `@tailwindcss/vite`, тип модуля ESM (`"type": "module"`), таргет сборки `es2020`.
- **Роутинг**: `react-router-dom` v6, `createBrowserRouter` + `RouterProvider`, ленивая загрузка экранов (`React.lazy` + `Suspense`) с фолбэком-скелетоном. Экраны — в `src/screens/`, конфигурация — в `src/router.tsx`.
- **Стили**: Tailwind CSS v4 (CSS-first: `@import "tailwindcss"`, `@custom-variant dark`, `@theme inline`, `@utility`) + shadcn/ui-примитивы (стиль *New York*, `components.json`, base color `neutral`). Дизайн-токены — `oklch`, радиусы `--radius`.
- **UI-примитивы**: Radix UI (Dialog, Label, Select, Slot, Switch, Tabs) из `@radix-ui/*`, собранные в `src/components/ui/` (Button, Card, Modal, Navbar, Table, Badge, Skeleton, Toast, StarRating, Breadcrumbs, EmptyState, Field, Tabs, Switch и др.).
- **Иконки**: `lucide-react`.
- **Уведомления**: `sonner` (Toaster по центру верх, `richColors`) через обёртку `ToastProvider`/`useToast`.
- **Утилиты стилей**: `clsx` + `tailwind-merge` → единая функция `cn(...)`.
- **Состояние**: контексты `AuthProvider` (`lib/auth.tsx`), `ThemeProvider` (`lib/theme.tsx`), `ToastProvider`. Глубокого стейт-менеджмента нет — состояние экранов локальное, данные персистятся в `localStorage`.
- **Провайдерная иерархия**: `ThemeProvider → AuthProvider → ToastProvider → RouterProvider` (`App.tsx`), обёрнуто в `StrictMode` (`main.tsx`).
- **Данные**: `localStorage` с префиксом `alfagen:` (onboarded, session, pendingAuth, configs, reviews, orders, settings).
- **Путь-алиас**: `@/*` → `src/*` (`tsconfig.json` paths + Vite alias).
- **Шрифты**: Google Fonts `Inter` (текст) + `Manrope` (заголовки), `display=swap`.
- **Форматирование**: нативный `Intl.NumberFormat` (`ru-RU`, рубли без копеек), даты «x дн назад», парсинг/формат RU-телефонов.

## 3. Функционал

- **Готовые ПК** — каталог с фильтрами (назначение, бренд, цена) и сортировкой (цена ↑/↓, рейтинг); состояние фильтров отражается в query-параметрах (`useSearchParams`). Карточки с рейтингами, отзывами, признаком наличия на складе.
- **Ручной конфигуратор** — выбор компонентов из каталога по 8 категориям с автоматической блокировкой несовместимых позиций в реальном времени; сводная панель (компоненты, потребление, итого).
- **Автоподбор** — пошаговый опрос из 4 шагов (бюджет, назначение, платформа Intel/AMD, приоритет — производительность/цена/тишина) с индикатором прогресса; автоматическая сборка оптимальной конфигурации.
- **Живая проверка совместимости** — сокет CPU ↔ платы; TDP процессора ↔ охлаждения (`coolTdp`); тип памяти DDR4/DDR5 платы ↔ ОЗУ; форм-факторы корпуса/платы/БП (ITX < mATX < ATX, SFX для ITX); длина видеокарты (`gpuLength`); высота кулера (`sizeMm` > 100 vs `cpuCoolerMaxHeight`); запас мощности БП (×1.6 к потреблению).
- **Сохранение и хранение сборок** — сохранение, загрузка, копирование в конфигуратор и удаление в профиле.
- **Оформление заказа** — детализация состава, итоговая сумма, попадание в историю заказов.
- **Рассрочка 0-0-4 от Альфа-Банка**:
  - Везде, где есть кнопка «Оформить заказ» (форм-экраны `CustomConfig`, `AutoResult`, `PcCard`), отображается кликабельный блок «Купить в рассрочку на 4 месяца от Альфа-Банка» с визуальным разбиением суммы заказа на 4 равные части — платежи привязаны к 4 следующим месяцам, начиная со следующего (первые ~`floor(total/4)`, последний — остаток).
  - Клик по блоку ведёт на отдельную форму оформления `/alpha` (аналогична обычному чекауту, но в красных оттенках и с атрибутикой Альфа-Банка — иконка карты, красные карточки/кнопки). Единственное базовое действие формы — кнопка «Отправить заявку на покупку в рассрочку».
  - Заявка раскладывается по компонентам (для конфигурации) или сохраняется как строка готового ПК; создаётся заказ со статусом «На рассмотрении в Альфа-Банке» (`status: "alpha"`), который отображается в разделе «Заказы» профиля.
- **Управление заказами** — в разделе «Заказы» профиля для любого заказа, кроме статуса «Выполнен», доступна кнопка «Отменить», удаляющая заказ из хранилища (функция `deleteOrder` в `lib/storage.ts`).
- **Профиль и авторизация** — вход по телефону (мок-SMS), режим гостя, разделы «Конфигурации / Заказы / Отзывы / Настройки».
- **Отзывы и рейтинги** — оставление отзывов к готовым сборкам, кастомному конфигуратору и автоподбору.
- **Темы оформления** — светлая/тёмная (oklch-токены), применяется до рендера (инлайн-скрипт в `index.html`), избегая мигания темы.
- **Онбординг** — гейт при первом посещении (`Layout.tsx` перенаправляет на `/onboarding`).

## 5. Архитектура и модули

- `src/types/index.ts` — доменные типы: `Part` (категория, спецификации, `tdp`, маркеры совместимости `socket`/`chipset`/`ramType`/`psuForm`/`formFactor`/`gpuLength`/`cpuCoolerMaxHeight`/`coolTdp`/`sizeMm`/`benches`), `Config`/`ConfigPart`, `ReadyPc`, `Review`, `Order`, `User`, `AppSettings`, `SurveyAnswers`, `PartIssue`.
- `src/data/mock.ts` — каталог компонентов по 8 категориям, готовые ПК, сид-отзывы.
- `src/lib/compatibility.ts` — движок: `configStats`, `checkPartCompatibility`, `validateConfig`, `isConfigComplete` (правила см. раздел «Функционал»).
- `src/lib/survey.ts` — автоподбор: бюджетные пресеты, score-функции по приоритету, генерация `Config` с `source: "auto"`.
- `src/lib/storage.ts` — персистенция в `localStorage` (ключи `alfagen:*`) + генератор `uid`; CRUD заказов (`getOrders`, `addOrder`, `deleteOrder`) и сборок.
- `src/lib/actions.ts` — сохранение/удаление сборок, шеринг в буфер обмена, отзывы.
- `src/lib/format.ts` — `formatPrice` (₽), `formatWatts`, `formatDate`, `formatAgo`, RU-телефоны, метки категорий и назначений.
- `src/lib/utils.ts` — `cn()`.
- `src/components/ui/` — переиспользуемые примитивы; `src/components/shared/` — композитные (ComponentPicker, ConfigPartsTable, ReadyPcCard, ReviewDialog, InstallmentPlan).

## 6. Экраны и маршруты

| Путь | Экран | Заметка |
| --- | --- | --- |
| `/` | Home | лендинг-зашивка на разделы |
| `/onboarding` | Onboarding | только при первой сессии |
| `/auth` | Auth | вход по телефону, мок-SMS, режим гостя |
| `/ready` | ReadyPCs | каталог + фильтры/сортировка (query-параметры) |
| `/ready/:id` | PcCard | карточка готовой сборки |
| `/config` | CustomConfig | ручной конфигуратор (8 карточек категорий + сводка) |
| `/auto` | AutoSelect | 4-шаговый опрос с индикатором прогресса |
| `/auto/result` | AutoResult | рекомендация; данные опроса в `location.state`, иначе EmptyState → `/auto` |
| `/profile` | Profile | по умолчанию «Конфигурации» |
| `/profile/:tab` | Profile | `configs`/`orders`/`reviews`/`settings` |
| `/checkout` | Checkout | оформление, состав, итог |
| `/alpha` | InstallmentCheckout | рассрочка 0-0-4 Альфа-Банк (красная тема, заявка) |
| `*` | NotFound | 404 |

Реализация экранов:
- 5 состояний данных: Loading (Skeleton), Empty (EmptyState), Error (message + retry), Partial (частично), Success.
- Конфигуратор блокирует действие до полной корректной сборки (`isConfigComplete`); несовместимые категории подсвечиваются с `role="alert"`.
- После выбора/удаления компонента или действия — toast-уведомление.

## 7. Основные принципы разработки UI

Роль: старший frontend-разработчик и UX-дизайнер, production-ready веб-приложения.

### 7.1 Фундаментальные принципы
- Визуальная иерархия: один первичная цель на экран, выделять размером/цветом/контрастом/расположением.
- Правило близости: связанные элементы группируются; внутри группы отступ меньше, чем между группами.
- Консистентность: единая сетка отступов (4/8-px), палитра, типографика, радиусы и тени (в проекте — Tailwind v4 токены + `oklch`).
- Узнаваемость: привычные паттерны (навигация сверху, гамбургер на мобильных); не выдумывать новые метафоры.

### 7.2 Типографика и читаемость
- Базовый размер ≥ 16px, line-height основного текста 1.5–1.75, заголовков 1.1–1.3.
- Максимальная ширина строки ~65ch; не более двух гарнитур (Inter + Manrope), чёткая шкала h1→…→small (коэффициент 1.25–1.5).

### 7.3 Цвет и контраст
- Палитра: один primary, акцент, нейтральная шкала (5–9 оттенков), семантические (success/warning/error/info).
- Контраст по WCAG 2.1 AA: 4.5:1 текст, 3:1 крупный. Не передавать информацию только цветом (добавлять иконку/текст).
- Интерактивные элементы: состояния default/hover/active/focus/disabled.

### 7.4 Компонентный подход
- Каждый блок — переиспользуемый компонент с чётким API, инкапсулирующий стили.
- Принцип единой ответственности: один компонент — одна задача.
- Базовый набор: Button, Input, Select, Card, Modal, Toast, Navbar, Table, Badge, Skeleton (все есть в `src/components/ui/`).
- Вариативность через пропсы: `variant`, `size`, `disabled`, `loading` (где уместно — `cva`).

### 7.5 Адаптивность и отзывчивость
- Mobile-first, min-width media queries; контрольные точки 320/640/768/1024/1280/1536.
- Flexbox и CSS Grid; избегать фиксированных пиксельных ширин контейнеров.
- Тач-цели ≥ 44×44px; проверка при масштабе 200%.

### 7.6 Интерактивность и обратная связь
- Мгновенный отклик (<100ms); переходы `transition: all 0.15s` (hover/focus), 0.25–0.35s (появление/скрытие).
- Асинхронные операции — индикатор загрузки (spinner/skeleton/progress).
- Модальные окна, тосты, dropdown закрываются по Escape и клику вне области.
- После успешного/ошибочного действия — toast (sonner), не `alert()`. Уважать `prefers-reduced-motion`.

### 7.7 Формы и валидация
- visible `<label>` c `for/id`; инлайн-валидация под полем (blur/submit).
- Конкретные сообщения об ошибках; обязательные поля — `*`, опциональные — «(необязательно)».
- Кнопка отправки блокируется с индикатором на время запроса; корректные `autocomplete`-атрибуты.

### 7.8 Доступность (a11y)
- Семантическая разметка (`header/nav/main/section/article/footer`), без `<div onclick>`.
- Полный доступ с клавиатуры, видимый `:focus`. `alt` для изображений, `aria-*` там, где недостаточно семантики.
- Контраст/размер/интерактивность по WCAG 2.1 AA; `prefers-reduced-motion`.

### 7.9 Состояния данных
Loading → Skeleton/spinner; Empty → иллюстрация + CTA; Error → сообщение + «Повторить»; Partial → частичные данные + индикатор; Success → данные.

### 7.10 Производительность восприятия
- Не более 7±2 элементов в группе; `loading="lazy"` для изображений ниже первого экрана.
- Шрифты с `font-display: swap`; критический CSS инлайн; избегать layout thrashing.

### 7.11 Структура и навигация
- Пользователь всегда знает, где он и как вернуться; хлебные крошки для вложенности >2.
- Активный пункт навигации выделен; логотип ведёт на главную.
- URL отражает состояние (роутинг, query-параметры для фильтров — реализовано в ReadyPCs).

### 7.12 Требования к коду
- Рабочий запускаемый код; зависимости явно (package.json); единый подход к стилям (Tailwind).
- Современные возможности: CSS custom properties, `clamp()`, `aspect-ratio`, `:has()`, container queries — где уместно.
- Комментарии только для неочевидного. Именование: kebab-case в CSS, PascalCase компоненты, camelCase переменные/функции.

### 7.13 Формат ответа при генерации UI
Структурированный ответ с разбиением на логические блоки (компонент → стили → данные → сборка).

### 7.14 Запрещённые паттерны
- ❌ `<div>`/`<span>` вместо семантических тегов.
- ❌ Inline-стили для повторяющихся элементов (использовать `cn()`/Tailwind).
- ❌ Магические числа в отступах без привязки к сетке.
- ❌ Текст-заглушка Lorem ipsum — только реалистичные данные.
- ❌ `alert()`/`confirm()`/`prompt()` (использовать toast sonner).
- ❌ Кнопки без `type="button"` внутри `<form>`.
- ❌ Иконки без текстового сопровождения или `aria-label`.

## 8. Код-стандарты и доступность (реализация)

- Тема применяется до рендера (инлайн-скрипт в `index.html`) для избегания миганий; `.dark` через `@custom-variant dark`.
- `Layout.tsx` оборачивает все экраны (navbar/footer + `Outlet`), реализует гейт онбординга/авторизации.
- Данные-заглушки реаклистичны; интернационализация — русский; формат цен/дат через `Intl`. Исполнение ненавязчивое, без спам-комментариев.

## 9. Установка и запуск

```bash
npm install
npm run dev      # dev-сервер http://localhost:5173
npm run build    # tsc + vite build (проверка типов + сборка)
npm run preview  # просмотр прод-сборки
```

Требования: Node.js и npm (ESM-проект, `"type": "module"`, таргет `es2020`).
